# Pulsea: экран ресепшена

Тестовое задание на позицию Frontend-стажёра. Администратор фитнес-клуба находит клиента, видит его абонемент, отмечает посещение и продаёт новый абонемент.

**Демо:** https://nonncal.github.io/pulsea-reception/

## Запуск

Нужен Node.js 22.12 или новее.

```bash
npm install
npm run dev
```

Приложение откроется на http://localhost:5173.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | сервер разработки |
| `npm run build` | проверка типов и сборка в `dist` |
| `npm run preview` | просмотр сборки |
| `npm test` | тесты логики (Vitest) |
| `npm run lint` | линтер (Oxlint) |

## Стек

React, TypeScript, Vite, Redux Toolkit, обычный CSS. Бэкенда и UI-библиотек нет.

## Структура

```
src/
  data.ts        моки из задания
  types.ts       типы
  lib/           правила абонементов, даты, поиск (без React)
  store/         Redux: слайс клиентов и сохранение в localStorage
  components/    список, карточка, продажа, история
```

## Решения и допущения

Там, где условие допускает разные прочтения, сделано так:

- В день окончания (`endDate`) абонемент ещё действует.
- День покупки входит в срок: 30 дней с 25.11 заканчиваются 24.12.
- Клиента можно отметить несколько раз за день. Рядом с кнопкой видно, сколько отметок уже есть, чтобы не списать занятие случайно.
- Если срок истёк и занятия закончились одновременно, статус «Истёк».
- Статус не хранится, а вычисляется из абонемента и сегодняшней даты.
- Дата берётся по местному времени, а не по UTC.
- Моки перенесены из задания без изменений.

## Данные

Изменения сохраняются в `localStorage` и переживают перезагрузку. Чтобы вернуться к мокам, выполните в консоли браузера и обновите страницу:

```js
localStorage.removeItem('pulsea-reception:clients:v1')
```

Статусы зависят от текущей даты, поэтому со временем абонементы из моков истекут.
